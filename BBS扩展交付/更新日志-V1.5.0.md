* 其余子设置页（可视化设置 / 关键帧处理设置）内容与排布顺序**完全不变**。

* 设置页「摄像机编辑设置」内新增子设置页 **「往期日志」**，恒定位于子设置页区域 **1 号位**（最上方）：

  * 其余子设置页（可视化设置 / 关键帧处理设置）**内容与排布顺序完全不变**，未误伤任何正常功能。
* **怎么用**：BBS「设置」→「摄像机编辑设置」→ 顶部第一项「往期日志」→ 滚动查看历史版本履历。

### 此前重要更新
## V1.5.3-Alpha（2026-10-10）

### 修复：与 BBS-Cubed 共存时，BCP 的「选择角色」显示样式优先生效

**成因**：玩家整合包同时装有 `BBS-Cubed-3.5.6+1.20.1.jar`（gbeic.bbsplusplus）。Cubed 同样 Mixin 接管了 `UIAnchorKeyframeFactory.displayActors`（滚动列表，条目显示为「key + formIdOrName」，即截图里的 `071cb8c1 - bbs:model`），且其注入先应用先执行，把本插件的「伪装名优先」菜单整个覆盖掉 —— 两个 mod 都有同功能修改时，显示跟了 Cubed。

**现在**：本插件 `UIAnchorKeyframeFactoryMixin` 的 Mixin priority 设为最低（0，默认 1000），注入在 Cubed 之后应用与执行，最终菜单由 BCP 接管，「伪装名优先」样式优先生效（有可辨识名直接显示名字；没有时「类型友好名 + 原 ID」兜底）。ID 串数据标识仍不动；Cubed 其他功能不受影响。

**实现**：`UIAnchorKeyframeFactoryMixin.java` 的 `@Mixin(value = UIAnchorKeyframeFactory.class, priority = 0)`。

### 修复：锚点「选择角色」列表显示名改为伪装名优先（不再被数据串替代）

**成因**：v1.0.3 的显示名方案把列表项拼成「ID 串 - formId - 伪装名」，未命名实体（如新添加的 `bbs:model`、`lumencore` 光源等）在列表里全显示成 `31ab03cd - bbs:model` 这类数据串，伪装名被压成后缀、甚至被数据串顶替，用户使用体验不佳。

**现在（显示名规则）**：

* 有可辨识名（优先级：自定义名 label → 表单名 form.name → 资产库同类型伪装名 → 影片内同类型演员名）→ **直接显示该名字**，不再带「ID 串 - formId」前缀；

* 确实没有可辨识名 → 「类型友好名 + 原 ID」兜底（如 `模型 31ab03cd`、`方块 605856a7`、`聚光灯 2b96e105`），不再满屏纯数据串。

**约束遵守**：

* ID 串作为 FS 核心数据标识**完全不动** —— 选择 / 存储的仍是 `Replay.getId()`，仅不再参与替代伪装名显示；

* 资产库（伪装）界面自身的**光标悬浮显示名**不受任何影响（名称反查仅发生在锚点列表内部，不回归集体覆盖 bug）。

**实现**：`UIAnchorKeyframeFactoryMixin` 的 `bcp$displayName` 重写 + 新增 `bcp$friendlyType` 类型友好名映射（`bbs:model`→模型 / `bbs:block`→方块 / `bbs:item`→物品 / `lumencore:spot_light`→聚光灯 / `lumencore:point_light`→点光源）。
