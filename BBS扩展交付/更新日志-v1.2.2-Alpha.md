## v1.2.2-Alpha（2026-10-08）

**新增：右键添加剪辑菜单改为多列网格选择面板（采纳 BBS Cubed 作者建议）**

* 摄像机编辑器右键添加剪辑不再是一长竖串菜单，改为「添加剪辑」多列网格面板：

  * 全部剪辑以网格排列，默认 2 列（同「可视性设置」面板风格）；
  * 面板顶栏左侧为「可视性设置」入口（原菜单顶部条目并入面板顶栏），右侧为「列数: N」开关，1 / 2 / 3 列循环切换，切换即时重建；
  * 剪辑条目保留原菜单的彩色标注，点击某项立即以右键位置添加该剪辑并关闭面板；
  * 「可视性设置」面板内的剪辑隐藏筛选同步生效于网格面板。

**弹窗恢复正式逻辑（取消实验版模拟行为）**

* 仅当检测到同一功能（剪辑可见性筛选 / 列数布局）来自多个模组时才弹窗：

  * 仅本插件提供 → 不弹窗，功能直接启用；
  * 检测到 BBS Cubed（bbsplusplus）也提供 → 弹出二选一询问窗口，选择后点击确定生效；
  * 按所选模组模式运行：选「Better camera perspective」→ 本插件功能激活；选「BBS Cubed」→ 本插件保持封锁（由对方功能接管）；
  * 选择持久化，重启后按保存的选择恢复，不再重复弹窗。

**更名**

* `better-camera-perspective-v1.2.2-Alpha.jar`

## v1.2.1-Alpha（2026-10-08）【实验版：冲突预防为模拟弹窗】

**新增：剪辑可见性筛选入口迁移 —— 右键菜单内「可视性设置」**

* 移除 BBS 设置页「camera perspective」（设置模块与配置代码一并删除，不再占用设置页）：

  * 原有设置页中的全部剪辑可见性开关随设置页移除；
  * 对应的 `camera_perspective.config.*` 语言词条同步清理。

* 改为在摄像机编辑器右键添加剪辑菜单中，于「静止」上方新增一个「可视性设置」项：

  * 视觉与其他剪辑条目融为一体（同菜单格式、带图标）；
  * 点击后弹出可视性筛选面板（overlay）：全部剪辑一行一个开关，逐项开启 / 隐藏，调整即时生效；
  * 筛选结果持久化到独立配置文件 `camera_perspective_clips.json`（不再依赖 BBS 设置系统，避免缺插件 / 异常状态崩溃）；
  * 每次进入摄像机编辑器自动恢复全开；再次打开「可视性设置」面板时自动应用用户先前保存的筛选。

**新增：与 BBS Cubed 同功能冲突预防（实验版）**

* 流程：功能封锁（用户不知情）→ 检测同型功能的不同来源 → 打开 BBS 界面时弹出询问窗口 → 选择模式并点击确定 → 恢复对应模式；

  * 检测对象：BBS Cubed（mod id `bbsplusplus`）—— 其作者将合并剪辑可见性筛选功能；
  * 仅本插件提供该功能（未检测到 bbsplusplus）→ 直接解除封锁，无弹窗；
  * 检测到冲突且用户未选过 → 弹出「剪辑可见性功能冲突」询问窗口（BBS Cubed / Better camera perspective 二选一 + 确定按钮）；
  * 用户选择持久化，后续会话按保存的选择恢复。

* 实验版行为（本次为模拟验证）：

  * 弹窗仅用于模拟与验证交互流程；
  * 无论选择「BBS Cubed」还是「Better camera perspective」，本插件功能都会被激活（封锁解除）；
  * 待后续正式版再实现「选中哪一 Mod 的模式，恢复哪一方功能」。

**修复（v1.2.1-Alpha 迭代中的问题）**

* 可视性设置面板打开后内容区空白：BBS 滚动列表需用 `UI.scrollView(...)` 工厂（内部列布局撑高子行），原实现包了中间容器导致行高为 0；改为工厂布局 + 每行开关直接挂滚动区。
* 冲突弹窗主文案过长被截断：缩短文案并新增灰色小字提示行。
* 实验版弹窗选择持久化导致重启后不再弹出：改为选择不落盘，每次新会话进入 BBS 都会弹出（模拟验证）；随后按 Cubed 作者反馈调整为「检测到 Cubed 即直接激活功能，弹窗仅提示」（最终在 v1.2.2-Alpha 恢复为正式二选一生效逻辑）。

**更名**

* `better-camera-perspective-v1.2.1-Alpha.jar`

## v1.2（2026-10-07）【经Alpha版本调整、修复后发布】

**新增：设置页「camera perspective」（剪辑可见性筛选）**



* BBS 设置界面新增设置页「camera perspective」（图标沿用摄像机编辑器视角图标）：


  * 可在其中按剪辑类型自由开关「摄像机编辑器右键添加剪辑菜单」中各剪辑的可见性；

  * 关闭后该剪辑不再出现在右键添加菜单中，减少过多剪辑占用的视觉空间；既有剪辑数据与功能不受影响；

  * 借鉴 BBS 源码中「筛选轴可见度」的思路（设置值 + 菜单构建时过滤）。

**修复：设置页「剪辑可见性」开关缺少翻译（体验不佳，后续已修复）**



* 根因：设置项注册用的真实剪辑 ID（如 `bbs:path` / `bbs:translate` / `bbs:shake` / `bbs:shake-comment` / `bbs:orbit` / `bbs:remapper` / `bbs:math` / `bbs:image-comment` / `bbs:dolly_zoom` / `bbs:hotbar` / `bbs:cinematic` / `bbs:replay` 等）与语言文件中补过的键对不上，BBS 设置面板对缺失词条回退显示 key 原文（`camera_perspective.config.clips.bbs:xxx`）；

* 修复：按 BBS 剪辑工厂真实注册清单补齐全部剪辑的中文 / 英文词条，设置页现在逐行显示中文名。

**修复（首发崩溃）**



* 进入 BBS 操作界面即崩溃：`UIClipsAddClipMixin` 中 `@Shadow getContext()` 无法在目标类 `mchorse.bbs_mod.ui.film.UIClips`（无 refmap 的 BBS jar）中定位 → 运行时 InvalidMixinException；修复为直接使用注入参数 `UIContext context`（`context.notifyError(...)`），不再 shadow 父类方法。

**更名**



* 版本号去掉 Alpha（包括某个未于此版本出场的抽风功能）：

`better-camera-perspective-v1.2.jar`

## v1.1（2026-10-06）

**新增**



* XYZ 双值面板行首两个锁定按钮升级为「主继承模式」开关：


  * 默认激活「相对值」—— 按钮高亮显示「将主继承相对值」；

  * 点击「绝对值」按钮 —— 高亮显示「将主继承绝对值」；

  * 切换只影响后续新建关键帧继承哪个值，不影响当前关键帧与视角；相对 / 绝对双值联动不变。

* 新建关键帧按主继承模式供给值：


  * 相对值模式：继承该 tick 的通道插值（相对偏移）；

  * 绝对值模式：继承 插值 + 该 tick 追踪锚点（绝对坐标）。

**实现 / 修复**



* 打点注入：`UIKeyframeDopeSheetMixin`（HEAD 注入 + 手动重放 BBS 打点逻辑，仅调用类 / 字段 public 成员）。

* 继承兜底：XYZ 通道 seed（无插值段 / 自动记录路径）。

* 构建期排查两次运行时崩溃：

1. `@ModifyArg` + 完整描述符 → 无 refmap → 注入失败崩溃 → 改为简单名 HEAD 注入；

2. `@Shadow` 绑定接口 default 方法（IUIKeyframeGraph.addKeyframeManually）→ 运行时 InvalidMixinException → 改为手动重放打点逻辑（不 shadow 接口成员）。

**更名**



* `better-camera-perspective-v1.1.jar`

## v1.0（2026-10-04）

**改动（大改）**



* 移除「三向轴模式」轴，以及受其影响的 XYZ 三轴属性面板内的「轴模式」开关。

## v0.1（0.1-Alpha，2026-10-02）

**新增**



* 新增剪辑「多样追踪」（multi\_tracker）：追踪器 + 关键帧二合一。


  * 继承「关键帧」剪辑的 8 个数值通道（X / Y / Z / 偏航 / 俯仰 / 横滚 / 视野 / 距离）与 additive 叠加开关；

  * 携带「追踪器」剪辑全部追踪参数（目标 / 附件 / 偏移 / 角度 / 看向目标 / 相对 / 启用位掩码）；

  * 「启用位掩码」6 位：位 0-2 = X/Y/Z 位移跟随，位 3-5 = 偏航 / 俯仰 / 横滚跟随，默认全开 = 纯追踪器；关掉某位后该轴改由关键帧曲线驱动。

* 拖动相机编辑：先按追踪器反解偏移 / 角度，再把相机位置写入关键帧曲线。

**修复**



* 锚点关键帧绑定其他演员时显示一串数据码：初版修复（formId 反查显示演员名）。
