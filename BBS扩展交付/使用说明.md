# BBS 扩展交付包 — Better camera perspective

版本 **v1.0**（2026-10-04）!!真正意义上的 追踪器剪辑 关键帧剪辑 优化二合一!!

基于你的 Fabric 模组工程「Better camera perspective」实现的 BBS FS 附加包，包含：

1. **新增剪辑「多样追踪」（multi_tracker）** —— 追踪器 + 关键帧二合一
2. **修复锚点绑定其他演员时显示数据码的 bug** —— 恢复演员显示名
3. **anchor 追踪轴（v0.3）** —— 追踪目标（演员+部位）随时间轴关键帧切换，跨演员平滑过渡
4. **XYZ 双值联动编辑（v1.0）** —— 关键帧值面板同时显示「绝对值 + 相对值」，改任一值另一个自动换算，无需再切换模式

1. 把 `better-camera-perspective-v1.0.jar` 放进 `.minecraft/mods`（Fabric 1.20.1，需要 fabric-api）。
2. 确保 BBS FS 2.7 在 mods 中（本包附带的 `bbs-2.7-1.20.1.jar` 可直接使用）。

   - `[BCP] 多样追踪 UI 面板 (UIMultiTrackerClip) 注册成功`

## 三、使用方法

### 1) 多样追踪剪辑
- 打开 BBS 影片编辑器 → 添加剪辑 → 列表中出现 **「多样追踪」**（橙色图标）。
- 面板从上到下：
  - **编辑**：打开 8 通道关键帧编辑器（X / Y / Z / 偏航 / 俯仰 / 横滚 / 视野 / 距离），与「关键帧」剪辑一致；
  - **叠加**：关键帧以叠加（增量）方式生效，同「关键帧」剪辑的 additive；
  - **目标 / 附件**：选择要追踪的演员与骨骼（同「追踪器」）；
  - **偏移 / 角度**：相对追踪点的偏移与视角角度；
  - **看向目标 / 相对**：lookAt 模式 / 相对模式；
  - **启用位掩码**（0-5 共 6 位）：位 0-2 = X/Y/Z 位移跟随，位 3-5 = 偏航/俯仰/横滚跟随。默认 6 位全开 = 纯追踪器行为；**关掉某一位后，该轴改由关键帧曲线驱动**——这就是「多样追踪」的玩法。
- 选中剪辑后拖动相机：先按追踪器方式反解偏移/角度，再把相机位置写入关键帧曲线（同「关键帧」剪辑的编辑行为）。
- 视野（fov）不做位掩码，始终由关键帧通道驱动（比原版追踪器更灵活）。

**XYZ 双值联动编辑（v1.0）**：
- 已移除「三向轴模式」通道与 X/Y/Z 的「轴模式」开关，不再需要切换「相对值 / 绝对值」模式。
- 选中 X/Y/Z 通道的关键帧时，值面板**同时显示两个数值**：
  - **相对值**：该视角相对于被绑定模型及部位（或默认位置）的相对偏移——编辑此值直接改变关键帧；
  - **绝对值**：该视角在地图上的绝对坐标——编辑此值也会自动换算并写入关键帧。
- 两个值**任改其一，另一个值自动同步转换**（绝对 = 相对 + 该时刻追踪锚点），数值始终一致、画面不跳变。
- 播放时 XYZ 关键帧按「相对值」语义生效（锚点 + 偏移合成）；不设追踪目标时相对值 = 绝对值。

### 1b) anchor 追踪轴（v0.3）
- 多样追踪关键帧编辑器在 X/Y/Z/偏航/俯仰/横滚/视野/距离 之外，新增 **「锚点」** 通道（蓝色）。
- 「锚点」通道的关键帧值 = **追踪目标**（演员 + 模型部位），原理同模型数据的 anchor 轴：
  - **通道无关键帧**（或关键帧为空值）→ 追踪目标使用剪辑属性的 **目标/附件** 绑定（与旧版行为一致）；
  - **通道有关键帧且值非空** → 该时刻追踪目标以 **anchor 轴数值为主**（覆盖剪辑属性绑定）；
  - **相邻关键帧绑定不同目标**（如 1tick 绑模型一头部、20tick 绑模型二脚部）→ 播放时在两个目标的追踪结果之间**平滑插值过渡**，避免画面跳变。
- 编辑方式：进入剪辑「编辑」→ 选中「锚点」通道 → 点击时间轴打点 → 在关键帧值面板选**演员**与**部位**（或使用吸管直接点选场景中的演员/部位），与 BBS 模型动画的锚点编辑一致。
- 与 XYZ 双值编辑独立：anchor 轴只决定**追踪目标**，XYZ 关键帧的「绝对值 / 相对值」由值面板双值联动自动换算，互不影响。

### 2) 锚点显示修复
- 进入某个演员/模型的表单编辑器 → 属性面板「锚点」→ 选择绑定到其他演员时，列表显示该演员的**名称**（如 `GM-L`），不再显示 `071cb8c1 - bbs:model` 这类数据码。
- 原理：锚点数据里存的是演员的稳定 ID，修复后会在当前打开的影片中反查回该演员的自定义名称。
- **v2 加固**：① 影片重新加载导致表单实例变化时，按表单类型匹配仍能反查；② 表单名称字段被写成稳定 ID（8 位 hex）时同样反查，不再显示数据码。

## 四、重新构建（改代码后）

```
gradle build --no-daemon
```
- Gradle 用户目录已指向 D 盘（`GRADLE_USER_HOME`），依赖走阿里云镜像（`init.gradle`）。
- BBS 依赖为本地 jar（`libs\bbs-2.7-1.20.1.jar`），Loom 自动 remap。
- 产物在 `build/libs/better-camera-perspective-v1.0.jar`（版本号在 `gradle.properties` 的 `mod_version`）。
