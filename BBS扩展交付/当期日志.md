## V1.7.21-Alpha（2026-11-22）【次级・游动⇄追踪衔接改为纯线性】

- 现象：游动与追踪的衔接段看起来像「淡入 / 淡出」（起步慢、中段快、收尾慢），但关键帧插值明确设为线性
- 原因：衔接段的两个端点各自走 `KeyframeChannel.interpolate()`，而 BBS 的关键帧带「前 / 后」手柄（duration / motionShift），
  每个关键帧附近都会被缓动；两端缓动后再按进度混合，叠出来的速度曲线就是 S 形
- 修复：过渡段（`routeBlend` 命中时）改为**按相邻两帧原始值线性插值**求两端
  - 新增 `linearFdAt()`：XYZ 帧值（游动值 / 追踪相对 / 追踪绝对）按原始值线性插值，模式位取左侧帧
  - 新增 `linearValueAt()`：偏航 / 俯仰 / 横滚同理
  - 混合进度仍用 anchor 段的原始 tick 比例，全程匀速，不再受关键帧手柄影响
- 影响范围：只有「游动 ⇄ 追踪」过渡段改用线性口径；纯游动段、纯追踪段仍按各自关键帧的插值 / 手柄表现

## V1.7.20-Alpha（2026-11-22）【次级・编辑器可见性分池 + 伪装选取生效】

### 1. 可视性筛选按编辑器分开（FOV / POV 动作编辑器不再共用摄像机池）

- 现象：FOV 编辑器的右键菜单里「可视性设置」打开的仍是摄像机编辑器的剪辑列表，
  勾选还会连带影响摄像机编辑器（两边共用了同一份 `Link → 可见` 映射）
- 修复：`BcpVisibility` 改为按「剪辑工厂」分池
  - 摄像机剪辑工厂 → 裸 Link 键（保持旧配置兼容）
  - 其他工厂 → `工厂类型键#Link` 键（与摄像机池互不影响）
- `openVisibilityPanel` 新增工厂参数，`UIClipsAddClipMixin` 把当前编辑器的工厂传下去，
  面板内容与菜单过滤都只针对本编辑器的剪辑

### 2. 「伪装选取」优先级真正生效

- 现象：设置里选 Cubed优先 后，伪装（演员）选取仍是 BCP 的分组列表 + 伪装名优先，
  设置页也一直呈现 BCP优先
- 原因：`getDisguiseMode()` 没有任何消费方，`UIAnchorKeyframeFactoryMixin` 无条件接管
  `displayActors`，所以行为恒为 BCP；配置里残留的 `bcp_first` 是当时补丁改写优先级留下的旧值
- 修复：`displayActors` 入口先判断模式 —— 选 Cubed优先 且检测到 bbsplusplus 时直接放行，
  交回 BBS / Cubed 原生演员列表；选 BCP优先 才走分组列表 + 伪装名优先 + 选后归零 XYZ

### 3. 剪辑类型菜单名接入翻译表

- 右键菜单与可视性面板里的剪辑类型名改为经 `BcpPovTrackTranslator.localized()` 过一遍翻译表
  （这类文本走 L10n 键，不经 `StringKey.get`，此前 POV 动作名残留英文）

## V1.7.19-Alpha（2026-11-21）【次级・遗留问题集中处理】

本版一次性处理此前记录的遗留问题（anchor 跳变、旧通道残留、游动相对冗余、求值重复、POV 菜单残留英文）。

### 1. anchor 跳变（核心）——统一采样器

- 新增 `AnchorSampler`：以「本帧有效关键帧 = 最后一个 tick ≤ 当前刻」为唯一口径，给出 `cur / next / t`
- 播放端不再使用 `anchor.interpolate()` / `anchor.previous` / `anchor.x`：
  BBS 的 `findRawSegment` 在整数刻会把段前移一格，叠加 `AnchorKeyframeFactory` 的「目标不同即硬切换」，
  导致每到一个关键帧刻就读到**下一帧**的目标状态 → 画面回跳再过渡。本版改为按采样器取本帧状态
- UI 端 `hasTrackTarget` / `anchorAxisAt` 与播放端同源：XYZ 双值与画面口径一致，本帧为空值时不再回退更早的绑定帧

### 2. 路线过渡方向修正

- `RouteBlend` 增加 `fromIsTrack` 方向标志：游动 → 追踪、追踪 → 游动 两种过渡按起点路线定向插值
  （原实现恒按「游动 → 追踪」方向，反向过渡会在起点外侧外插，表现为先冲出去再回来）

### 3. 旧 Double 通道隔离（问题 5）

- `fdAt` 改为：新档 `xd / yd / zd` 只要有帧就一律以它为准；当前刻落在无段区间时返回 null，
  不再回退父类老通道，避免老通道残留的 tick 0 默认帧把画面钉成常数
- 父类 `x / y / z` 仅在 `xd` 完全为空（老存档）时才作兜底，兜底值按帧级口径构造

### 4. 移除游动（游离）的「相对」子模式（问题 8）

- `UIXyzKeyframeFactory` 删除游动「相对」按钮与相对值框，只保留「游动 · 绝对」标识（静态不可点，仍为品红）
- 游动值恒等于相机世界绝对坐标；`XyzFrameData.roamMode` 保留为历史兼容字段，新写帧一律 `1`
- 老工程 `roamMode == 0` 的帧仍在播放端按 `roamValue + offset` 读取，画面不偏移；用户在 UI 改值后静默迁移为绝对

### 5. 播放期 track() 求值缓存（问题 6）

- 同一帧内「目标 + 朝向模式 + 参考点」相同的 `track()` 结果直接复用，
  避免主目标 / 过渡端 / 相位追踪对同一目标重复求解并重复走 `applyUnderneath`

### 6. POV 动作菜单残留英文（问题 2，兜底）

- `translate()` 在「第三方（Cubed）优先」模式下改为「Cubed 未覆盖 → BCP 表兜底」，
  Cubed 3.6.8 新增的 ITEM_SPRAY / AAA_PARTICLE / VFX 等表不覆盖 POV 动作菜单名（Menu / Camera Shake / Particle Effect 等），
  此前会原样显示英文
