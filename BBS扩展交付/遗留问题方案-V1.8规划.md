## 一、主导问题：anchor 未绑定 ⇄ 绑定 多次切换时播放跳变

### 1.1 现象（来自录屏与描述）

anchor 轨道关键帧值在「未绑定」与「绑定」之间反复切换（A1 未绑定 → A2 绑定 → A3 未绑定 → A4 绑定 …）时：

- 播放每到达一个关键帧所在刻，镜头**先切到某个固定画面**，再向下一关键帧过渡；
- 到达下一个关键帧刻时，又**切回同一个固定画面**，再继续过渡。

即每个关键帧刻都出现一次「回跳 → 再过渡」的破绽。

### 1.2 已核实的结构性事实（来自反编译 bbs-2.7-1.20.1）

**事实 A：整数关键帧刻会前移到下一段**

`mchorse.bbs_mod.utils.keyframes.KeyframeChannel#findRawSegment` 内：

```java
if (keyframe.getTick() == (float) Math.floor(tick) && index < size - 1) {
    index++;                       // 前移
    keyframe = list.get(index);
}
```

即当 tick **恰好等于**关键帧 K_i 的刻时，返回的段是 `<a = K_i, b = K_{i+1}>`，进度 x = 0（而不是 `<a = K_{i-1}, b = K_i>` 且 x = 1）。

**事实 B：Anchor 关键帧工厂是离散硬切换**

`mchorse.bbs_mod.utils.keyframes.factories.AnchorKeyframeFactory#interpolate`：

- 若 `b.hasSameTarget(c)`（相邻两帧目标相同）→ 返回 c 的副本并按 Transform 插值（正常连续）；
- 否则（目标不同）→ **直接返回 c（下一帧）的副本**，把 b 塞进 `previous`，`x` 存进度。

也就是说：只要相邻两帧目标不同，**整段的插值结果都是「下一帧的目标」**，「上一帧」只存在于 `previous` 里，需要调用方自己拿 `x` 做过渡。

**事实 C：同一个 tick 目前有三套互不相同的采样口径**

| 位置 | 采样方式 |
| --- | --- |
| `MultiTrackerClientClip.applyClip` 步骤 1 | `this.anchor.interpolate(tick)` → 受事实 A+B 支配，整数刻直接读到**下一帧**目标，且整段都超前 |
| `MultiTrackerClientClip.routeBlend` | 手工扫描「last ≤ tick」/「first > tick」 → 段首读**本帧**，段尾读**下一帧** |
| `UIMultiTrackerClip.anchorAxisAt`（UI 双值换算） | `interpolate(tick)`，取不到目标再 `nearestAnchorAtOrBefore` 兜底 → 第三套 |

### 1.3 判定

跳变不是"插值算法写错"，而是**路线判定口径分裂**：

> 在关键帧刻，锚点采样（`interpolate`）瞬间切到「下一帧」的目标状态，而 XYZ 帧值仍然是「本帧」的 —— 于是这一刻 `hasTrackTarget` 与 `routeBlend` 得出互相矛盾的路由，游动端与追踪端被错配拼接，画面先被拉到一侧（某个固定画面），再按段进度过渡回来。

「切回同一个固定画面」的具体落点取决于该刻被判成游动后取到的 `roamValue`（游动端世界坐标）——这正是每帧都要回跳、且每次都回到同一处的原因。

### 1.4 修复方案对比

| 方案 | 做法 | 优点 | 缺点 | 风险 |
| --- | --- | --- | --- | --- |
| **A（推荐）统一采样器** | 新增 `AnchorSample sampleAnchor(KeyframeChannel<Anchor>, float tick)`：① 取 last ≤ tick 作 cur、first > tick 作 next；② cur 空值 → 回落剪辑属性；③ cur 有目标 → 追踪，否则游动；④ cur/next 目标不同 → 给出过渡进度 t。播放端步骤 1、`routeBlend`、`hasTrackTarget`、UI `anchorAxisAt` 全部改为调用它 | 一处实现、四处同口径；彻底消除整数刻前移影响；不必碰 BBS 数据格式 | 改动面覆盖播放端 + UI 端共 4 处，需整体回归 | 中 |
| **B（最小改动）规避整数刻** | 采样时统一用 `tick - 1e-4`（或在整数刻显式取「本帧」） | 改动只有几行 | 仍是两套逻辑拼接，段内超前问题依旧存在；边界靠 epsilon 硬撑，长时间轴可能露馅 | 低但治标 |
| **C（替换工厂）** | 给 anchor 通道注册自有工厂，复刻 BBS 版但去掉整数刻前移 | 从数据层根治 | 需兼容 BBS 的序列化 / 关键帧编辑 UI / 存档迁移，回归面积最大 | 高 |

### 1.5 推荐方案 A 的实施步骤

1. **新增 `AnchorSample`**（内部类或独立小类）：字段 `cur`、`next`、`t`、`routeIsTrack`、`hasTarget`；一个静态方法完成采样。
2. **播放端改造**（`MultiTrackerClientClip`）：
   - 步骤 1 的目标解析改用 `AnchorSample`，删除对 `anchor.previous` / `anchor.x` 的依赖；
   - `routeBlend` 直接复用同一份 `AnchorSample`（不再自己扫描），过渡进度用 `sample.t`；
   - `hasTrackTarget(clip, tick)` 改为走采样器结果，保证与播放端完全一致。
3. **UI 端改造**（`UIMultiTrackerClip`）：
   - `anchorAxisAt`、`insertFrameKeyframes`、`frameSeedValue` 统一走采样器，去掉「interpolate 失败再 nearest 兜底」的双重逻辑。
4. **不动的部分**：`XyzFrameData` 五字段结构、`roamValue / trackRelative / trackAbsolute` 语义、存档格式全部保持不变 —— 老存档无需迁移。

### 1.6 验证方法

**先加临时诊断日志（方案实施前先跑一遍，锁定真实落点）**

在 `applyClip` 每帧打印一行：

```
tick | hasTrackTarget | routeBlend.t | anchor.replay | xd.roamValue | xd.trackRelative | 最终 X/Y/Z
```

对比三处得出的路由是否一致；重点看 tick 恰为整数关键帧刻的那几帧。

**回归场景（三个必须全过）**

1. 未绑定 → 绑定 → 未绑定 → 绑定，四段各 ≥ 10 tick，全程不得回跳；
2. 绑定 → 未绑定（反向切换）同样不得回跳；
3. 相邻两帧绑定**同一**演员但**不同部位**（走连续插值分支），不得出现画面卡顿或瞬移。

### 2.1 新增项（问题 8）说明：移除游动（游离）的相对子模式

**现状**

`UIXyzKeyframeFactory` 把 XYZ 分成两块：游动（游离）与追踪，每块各有「相对」「绝对」两个按钮、两个数值框：

- 游动·相对：世界坐标 = `roamValue + offset`（offset 是剪辑「偏移」调试值）
- 游动·绝对：世界坐标 = `roamValue`
- 追踪·相对：世界坐标 = 锚点 + `trackRelative`
- 追踪·绝对：世界坐标 = `trackAbsolute`

游动的两个小模式本质是同一个量，只是差一个调试偏移，切换时还要在 `setRoamMode` 里来回加减 offset——属于冗余状态，容易在切换中产生数值漂移。

**改造目标**

- 游动只保留「绝对」一种语义：`roamValue` 恒等于相机世界绝对坐标；
- UI 上删掉游动「相对」按钮与相对值框，**保留「游动 · 绝对」标识文本**（作为不可点选的静态标识，仍显示品红 0xFFFF6666），让用户一眼看出这一组是游动且是绝对坐标；
- 游动组从「2 按钮 + 2 数值框」收敛为「1 标识 + 1 数值框」，整块面板从 8 个数值框降为 7 个（游动 1 + 追踪 2 + …）。

**数据兼容（关键）**

`XyzFrameData` 的五字段结构**不改**，`roamMode` 字段继续序列化：

- 新写入帧一律 `roamMode = 1`；
- 旧存档中 `roamMode == 0` 的帧，播放端 `roamWorld` 仍需保留 `roamValue + offset` 分支，保证老影片画面不偏移；
- UI 读取时不再展示相对态，直接以「绝对」口径显示（旧帧显示 `roamValue + offset`），用户改值后按绝对写回并置 `roamMode = 1`，完成静默迁移。

**改动点**

| 位置 | 改动 |
| --- | --- |
| `UIXyzKeyframeFactory` | 删除 `roamRelativeButton` 与其数值框；`styleButton` 只对「游动·绝对」做选中样式；`setRoamMode` / 游动值的相对分支收敛为绝对口径；`refreshValues` 游动只刷一个框 |
| `MultiTrackerClientClip#roamWorld` | 保留 `roamMode == 0` 的旧帧分支作为兼容，注释改为「历史相对态兼容」；新帧走绝对 |
| `UIMultiTrackerClip#insertFrameKeyframe` / `frameSeedValue` / `defaultInheritValue` | 写帧时显式 `roamMode = 1`，不再依赖默认 0 |
| `XyzFrameData` | 仅补注释：`roamMode` 为历史兼容字段，新数据恒为 1 |

**回归**

- 新工程：游动段只认绝对坐标，拖动相机打点后画面即时贴合；
- 老工程：含 `roamMode = 0` 的旧帧播放画面与升级前**完全一致**（不因移除相对态而偏移）；
- 追踪段不受影响：追踪的「相对 / 绝对」两组保留原样。
| 7 | 粒子 ID 翻译 | 按既定口径**不处理** | 保持跳过 | — |
