### 版本迭代逻辑

**核心原则**：全新功能走主版本号 +1，小修复走次版本号 +1；两者都在 Alpha 实验线迭代，测试通过后才转正。

```
正式版基线（如 V1.7）
   │
   ├─ 全新大功能开发 ──→ V1.8.X-Alpha（X 从 0 起，每次修正 +1）
   │                     ↓ 测试通过 + 用户许可
   │                   转正为 V1.8（正式版）
   │
   └─ 小调整 / 修复 ───→ V1.7.X-Alpha（X 接续之前的迭代号，如从 14 起）
                         ↓ 测试通过 + 用户许可
                       转正为 V1.7.1（正式版次版本号 +1）
```

**示例（当前实际履历）**：
- V1.6.2（正式版）→ 做 POV 翻译全新功能 → V1.7.0-Alpha ~ V1.7.13-Alpha → 转正为 **V1.7**（正式版）
- V1.7 正式版后做小修复 → 继续在 V1.7.X-Alpha 迭代（从 V1.7.14-Alpha 起）→ 转正为 **V1.7.1**
- V1.7.1 后再做全新功能 → V1.8.0-Alpha → 转正为 **V1.8**

**转正条件**：
1. 实验线功能经实测达到预期；
2. 用户明确许可（说"转正"/"转正为 Vx.x"）。

## 三、更新维护逻辑（每次发版必做）

### 3.1 发版流程

```
1. 修改 gradle.properties 版本号
2. gradle build 构建
3. jar/sources 复制到 BBS扩展交付\（当期）
4. 旧版 jar/sources 移到 往期mod版本\ / 往期源码\（归档不删除）
5. 更新日志：
   - 当期日志：更新日志-V<版本号>.md（新写或追加）
   - 往期日志：往期日志.md（顶部补最新版本条目）
6. 使用说明.md：版本行同步更新
7. 项目进度与维护手册.md：版本号、功能清单同步更新
8. git add -A && git commit
   - 注意：.tmp_cubed363 已在 .gitignore，无需手动排除
   - 注意：LumenPointLightAlphaMixin.java（黑光实验废弃文件）仍需手动 git reset 排除
```

### 3.2 日志管理规则

| 文件 | 位置 | 作用 |
| --- | --- | --- |
| 当期日志 | `BBS扩展交付\更新日志-V<版本号>.md` | 当前最新版本的详细更新说明 |
| 往期日志 | `BBS扩展交付\往期日志.md` | 所有历史版本的整合履历（最新→最旧排列） |
| 使用说明 | `BBS扩展交付\使用说明.md` | 功能说明 + 安装指南 + 燃眉之急对照 |

**归档规则**：
- 新版本转正后，旧的当期日志文件（如 `更新日志-V1.6.2.md`）如果已完整录入往期日志，可删除
- jar/sources 旧版本不删除，归档到 `往期mod版本\` 和 `往期源码\`
- 老版 jar/sources 是用户要求保留的，不删除

### 3.3 Git 提交规则

- 每次发版一次提交，提交信息格式：`V<版本号>: <一句话说明>`
- 示例：`V1.7: 转正正式版，整合V1.7.x-Alpha POV中文翻译补充`
- 不做 --amend，不做 --no-verify

## 六、功能冲突检测系统（V1.7.1 新增）

### 6.1 设置页结构

设置页左侧导航 2 号位（1号位往期日志之后）：
1. 往期日志
2. **功能冲突检测** ← 新增
3. 剪辑处理设置
4. 关键帧处理设置

### 6.2 自动检测逻辑

每个功能独立统计来源数（BCP=1，检测到其他插件+1），来源数 ≥ 2 才显示对应按钮组：

| 功能 | 按钮数 | 说明 |
| --- | --- | --- |
| POV 轨道名翻译 | 3 | 第三方优先 / BCP优先 / 第三方为主BCP辅助 |
| POV Actions 属性面板翻译 | 3 | 同上 |
| 伪装选取 | 2 | 第三方优先 / BCP优先（无主辅模式） |

### 6.3 调试日志

搜 `BCP-` 前缀即可定位：
- `BCP-PovTranslator`：翻译表初始化、反射绑定、首次翻译模式
- `BCP-KeyframeSheet`：hook 首次触发
- `BCP`：冲突检测各功能来源数统计
