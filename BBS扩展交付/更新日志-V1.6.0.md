### 转正说明：V1.5.4 整合后成功的核心修复

V1.6.0 把 V1.5.4-Alpha 实验线里**验证成功、不再回退**的两大核心修复整合为正式能力：

**核心修复①：多样追踪三大相机关键帧异常（根治「选模型锁 0 / 角度差圈 / XYZ 飞回原点」）**

- 锚点选定模型后 XYZ 相对值**只归零当前播放头帧**（其余帧保留），不再清空三轴通道全部关键帧；
- 新建关键帧继承的角度值统一**归一化到 (-180, 180]**，修复"方位正确但数值差一整圈、播放极高角度水平旋转"；
- 连锁故障（新建剪辑选模型后 XYZ 锁 0 / 相机回原点）随①消失；
- **空 XYZ 通道不再补 0 值帧**（二版加固）：`resetChannel` 仅当当前 tick 已有关键帧才归零，绝不插入新帧 —— 彻底杜绝"锁 0"。

**核心修复②：位置存储架构重构（每帧独立「游动 / 追踪」值，跨路线连续插值）**

- 新增帧级数据类 `XyzFrameData` 与三个帧级通道 `xd / yd / zd`，每帧独立存储游动 / 追踪四值（`roamValue` / `trackRelative` / `trackAbsolute` + 各自小模式），删除剪辑级共享模式字段；
- 游动 / 追踪值不再共用单一 double 池，编辑互不污染；
- 锚点绑定变更只更新当前 tick 已存在的帧，绝不新增帧、不影响其他帧；
- 游动 ⇄ 追踪相邻帧路线状态不同时，按段内进度对位置逐分量 lerp、角度走最短弧 lerp，跨路线机位切换变为连续动画而非瞬间跳转；
- **老存档兼容**：播放端优先读新帧级通道，空则回退父类旧 Double 通道，不打开编辑器直接播放也不丢机位、不崩。

### 次级 更新、修复（所有，继承自 V1.5.4-Alpha 实验线）

- **角度双值**（三版）：偏航 / 俯仰 / 横滚关键帧「调试（-360~360）+ 正式（不限，多圈换算）」双值联动；

### 修复：重进客户端后 X / Y / Z 关键帧被删除（存档持久化修复）

- **问题**：关闭重进客户端后，「多样追踪」剪辑内 X / Y / Z 三轴（帧级通道 `xd / yd / zd`）的关键帧会被整段删除，长时间编辑的机位全部白费（V1.5.4-Alpha 十版引入帧级通道后出现的遗留问题）。
- **根因**：BBS 的 `KeyframeChannel` 序列化**不认「通道自带的工厂实例」**，而是按**全局类型名**存取——存档时用 `KeyframeFactories.FACTORIES` 反查工厂名写入 `type`，读档时再用该名 `FACTORIES.get(type)` 取回工厂。`xd / yd / zd` 的 `XyzFrameDataKeyframeFactory` 未注册进该全局表 → 存档写出的 `type` 为 `null` → 读档时 `FACTORIES.get(null)` 为 `null`，该通道 keyframes 被整段丢弃（`"has unknown value type … its keyframes are left out"`）。
- **修复**：把 `XyzFrameData` / `XyzFrameDataKeyframeFactory` 从 client 侧移到 common 侧（`perspective.better_camera_perspective.data`），并在 addon 入口订阅 BBS 官方扩展点 `RegisterKeyframeFactoriesEvent`，以稳定类型名 `bcp_xyz_frame` 注册该工厂。存档 / 读档自此可正确往返，XYZ 关键帧不再丢失。
- **注意**：此前用旧版本保存、已被写坏的影片（其 `xd / yd / zd` 的 `type` 为 `null`）无法自动恢复；本修复后新建 / 重存的影片正常持久化。类型名 `bcp_xyz_frame` 一经写入存档务必保持稳定，改名会导致旧存档读不回。
